# Mode 1 — Inspector (finished claims)

**Trigger:** the user brings a *finished* piece of language to test — a judgment, slogan, thesis,
critique, argument, manifesto, or reflective passage. Not an open problem (→ Mode 2), not a text to
re-voice (→ Mode 3).

This mode is inherited whole from the original `wittgenstein-language-inspector`. It is not
re-derived here. The procedure, output format, translation rules, hinge-sensitivity block, failure
modes, and demonstration cases stand as written. What follows is (a) a one-screen recap so the mode
is usable without the old file, and (b) the two places where the newly distilled texts *sharpen* an
existing step.

## Recap of the inspection procedure

1. **Extract the judgment.** Quote or paraphrase the central judgment; if several, separate them.
   Don't analyse a fog as one proposition.
2. **Break into smaller propositions.** Claims, metaphors, definitions, implications, evaluations.
   Mark which carry the burden and which are prestige-bearing ornament.
3. **Identify key terms.** For each: what is it doing here — naming, classifying, evaluating,
   excusing, dramatising, concealing? Where is it at home? What examples would teach its use?
4. **Locate the language-game.** Who says it, to whom, in what practice, with what consequence? If
   no practice can be named, say the game is missing or only gestured at.
5. **Ask for criteria.** What would count as right, as wrong, as a misunderstanding? Could a
   competent participant be corrected? If no criteria: either it is not yet a usable claim, or it is
   not meant as a claim (expression, slogan, rule, hinge).
6. **Classify the function.** Empirical / grammatical / rhetorical / expressive / programmatic /
   hinge-like / confused. Fix function before judging truth.
7. **Detect slips.** Words gesturing without criteria; metaphors read as reports; category
   mistakes; explanatory mirages; false pictures from grammar; inflated abstractions; pseudo-depth
   by nominalisation; empirical doubt confused with background certainty.
8. **Separate surviving content from residue.**
9. **Translate into plain language**, preserving real force; if several meanings, list them; if
   nothing definite remains, say so.

**Output format** (unchanged): *The Judgment · What Is Being Said · What Has a Clear Use · What Only
Seems to Say Something · Where the Language Slips · What Would Count as a Test or Clarification ·
Plain-Language Version · (If Needed) Remarks.*

## Sharpening 1 — aspect-seeing feeds "What Is Being Said"

From RPP / PI Part II (see `references/clusters/rpp.md`, `pi.md`).

When you write **What Is Being Said**, the old default was to hunt for the single thing the sentence
asserts. Add a prior question: *is the disagreement here factual, or a difference of aspect?* The
same words, the same facts, can be *taken* two ways — the figure that is now a duck, now a rabbit;
the schematic cube that flips. Seeing-as is not neutral seeing with an interpretation bolted on; the
aspect **dawns**, and the report "I see it *as*…" is an expression, not a further observation.

Practical effect on the step:
- Where a passage seems to state a fact, ask whether it is instead **presenting an aspect** — urging
  you to see X *as* Y. "The market is a conversation," "the cell is a factory," "grief is love with
  nowhere to go" often do this. They are not false; they organise seeing.
- Then the criteria question changes shape (step 5): you no longer ask "is this true?" but "what
  does this aspect let us notice, and what does it hide?" An aspect can be apt or inept without
  being true or false.
- Flag **aspect-blindness** as its own diagnosis: a reader who can only take the sentence one way,
  and treats the other party as making an error, when both are seeing one thing under two aspects.

## Sharpening 2 — rule-following feeds "What Would Count as a Test or Clarification"

From RFM / PI §§185–242 (see `references/clusters/rfm.md`, `pi.md`).

The old step asked what would settle or clarify the matter. When the claim turns on **correct
application of a rule, standard, definition, or precedent**, deepen it: the rule does not carry its
own applications inside it. "Going on in the same way" is fixed by a practice, not read off the rule
by pure interpretation — there is a way of grasping a rule that is not an interpretation, shown in
what people do. So "what would count as getting it right?" becomes:

- *In whose practice, and by what training, is "the same" fixed here?* A test that presupposes the
  rule already settles every case is no test.
- For a disputed edge case, don't ask the rule to adjudicate itself. Ask what the community of
  practitioners actually does, what they would correct, and where the rule genuinely runs out and a
  fresh decision (not a further reading) is being made and then hardened into a new paradigm.
- Watch for the false picture of the rule as **rails laid to infinity** — as though every future
  application were already present in the sign. That picture is exactly the one to name (core move 2).

## Notes

- Keep everything the original file bans: no fake aphorisms, no biography, no Viennese mystique, no
  academic inflation, no motivational language, no generic critical-thinking advice, no lecture on
  analytic philosophy, no secondary literature unless asked.
- When the input is not actually a finished claim but an open problem or a text to re-voice, switch
  modes rather than forcing the inspection format onto it.
